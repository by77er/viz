Rows of comparable things. `vz-table` inside `vz-table-wrap`, with `vz-label` column heads on `sunken`.

- The identifying column is first, in `ui-strong` (`data-key`). If the row leads somewhere, the key holds the link, and **the link fills its cell**: the whole key cell is the target. A long identifier is cut in the middle with `vz-cut` (its start and its distinguishing end, the whole in `title`), capped at half the measure, so the figures beside it stay on screen.
- Numbers are `vz-num`. A column of one unit is `vz-right` with the unit in its head ("p99, ms") and bare numbers in the cells. A column of mixed units ("912 ms", "4 min 10 s", "1.3%") is left-aligned, each cell with its unit (see Number). A left-aligned column after a right-aligned one starts `space-6` in, so figures do not run into words.
- Rows are `row` tall and separated by `rule`; the hovered row is `hover`. No zebra striping, no vertical rules. **With a coarse pointer, rows that hold a link or a control are `control-touch` tall**, so a target in a row has its 44px without reaching into the next row; a table of figures with nothing to tap keeps its density.
- **The row whose detail is shown** (the trace open beside the list) is `aria-current` (or `aria-selected` in a selectable list): `rule` fill and an `ink` edge on its key, like a chosen segment.
- State is a `vz-status`, never a coloured cell. **Row actions** go in a menu: a quiet small button "Actions…" in the last cell (`td.vz-row-actions`, Menu).
- **Caption.** A table in a panel starts with `vz-table-caption`, one `small` line in `ink-secondary` that says how many rows of how many and in what order ("3 of 41 routes, slowest first"). It is the view's strip: `space-6` tall, `control-touch` with a coarse pointer; a waiting line lies over it (Panel). A table that shows some of its rows always has one.
- **Sortable head**: a `button.vz-sort` inside the `th`; the `th` carries `aria-sort`. The sorted head is `ink` and strong with a triangle (up for ascending, down for descending); the triangle's space is always reserved, so sorting moves nothing. In a right-aligned column the triangle is on the left. Hover is `hover`, a press is `pressed`, painted at once. Say the initial order in the caption if it is not the first column's.
- **Wide table in a narrow region, two forms.** Choose per table:
  - *Scroll* (default): the wrap scrolls sideways and the first column stays in place. For tables people compare across many numeric columns.
  - *Fold* (`data-fold` on the table): below `breakpoint-narrow` of table width (`data-fold="wide"`: below `breakpoint-wide`, for a list whose columns do not fit in 640px, such as Monitors at 200% zoom), columns marked `data-priority="1"` stay as columns beside the key (each `keep` wide), and every other column folds into a line under the key, in source order, each cell preceded by its `data-label` in `ink-muted` and its words in `ink`. Write each quantity in a kept column as a `vz-qty`, and a pair of phrases as `vz-phrase` spans ("&gt; 500 ms" "for 5 min"), so a narrow column wraps between phrases, the same way in every row. Only the key's head stays sortable in the folded form. Nothing is hidden and nothing needs a second tap. For lists a person reads row by row, especially on a phone: monitors, dashboards, keys. Mark as priority 1 the one or two columns the list exists for ("Now", "Threshold"), not the ones that are merely short.
  - Give a folding table explicit roles (`role="table"`, `row`, `columnheader`, `cell`), because the folded layout replaces the table display.
  - A row expander was considered and not used: it hides the columns behind a tap per row, which is the wrong cost for a person scanning a list at night.
- The page never scrolls sideways.
