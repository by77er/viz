## Principles

1. **The data comes first.** The interface exists so that someone can read a system's state and act. When a choice makes the data easier to read, take it, even if it is plainer.
2. **Each element answers a question.** Before adding an element, name the question it answers for the person looking at it. If removing it loses nothing, remove it. This applies to rules, labels, icons, colours and words alike.
3. **Colour marks action, state and data.** The interface is neutral. `blue`, `red`, `green` and `yellow` appear only where a person can act; status colours only where state needs attention; series colours only in a chart.
4. **Two typefaces, each with one job.** One sans family carries reading and interface text; one monospace carries data. Hierarchy comes from size, weight and space.
5. **Every input answers in the next frame, and every answer is true.** Anything slower says what it is doing, measured, and never pretends. Words about data describe the data on screen, never the request in flight.
6. **Every view has a text form.** Each view has a visual form, a text form and a structured form. Design the text form with the same care.

## Colour

- Build every screen from `ground`, `sunken`, `ink`, `ink-secondary`, `ink-muted` and `rule`. A finished screen with no data on it should contain no colour at all.
- `ground` is the page. Use `sunken` for wells that recede: table heads, code, the query editor. Use `hover` for the row, item or quiet button under the pointer; it is a highlight in both themes and is never used for wells. Use `pressed` for an untoned control while it is held down or busy, and `rule` for what is chosen (a segment, a legend row): a press must look different from both. Use `raised` only for overlays, always with `shadow-overlay`, and `scrim` only behind a dialog.
- Separate regions with `rule`. Give inputs and secondary buttons a `rule-control` border; it is the only border that has to be seen to be used.
- **Action colours.** `blue` is the primary action: at most one blue button in a view. `red` deletes or destroys. `green` affirms (resolve, acknowledge). `yellow` cautions (silence, snooze). Set their labels in `on-blue`, `on-red`, `on-green`, `on-yellow`. Each has a `-hover` and a darker `-pressed` fill, so a press shows even when the pointer was already over the button. The four values are the same in both themes.
- **Status marks** have their own tokens, `status-critical`, `status-warn`, `status-ok` and `status-info`, which are lighter in the dark theme so no state dominates. Each state also has its own shape (solid square, diamond, hollow square, bar; a dash for unknown), followed by a word in `ink`. Shape and word carry the state; colour reinforces it. Never colour the word. Button colours are not used for status, and status colours are not used for buttons: `status-info` is a cyan, never the action blue.
- **What a person has done** about a state is neutral, in `ink-secondary` or `ink-muted`, with its own shape and word: acknowledged (half-filled square), silenced (two bars), ruled out (a slash). The severity colour stays only while nobody has the problem (Status).
- Do not tint backgrounds with action colours, do not use them for text, borders, icons or decoration, and never use a gradient as a fill or an effect. (The select's arrow is drawn with two hard-stop gradients in `currentColor`, because a select cannot hold an element; it draws a triangle, not a change of colour, and it is the only one.)
- Links are `ink` with an underline. Selection is `ink` in `ui-strong` on `rule`, or with an `ink` underline for tabs and navigation. Selection is never inverted and never blue: choosing a view must not outrank the primary action.
- The focus ring is `stroke` wide in `focus`, offset by `stroke`, outside the element, on every focusable element; inside a box that clips it (a strip that scrolls, a legend, a head the control fills) it is drawn inside the control, offset by minus `stroke`, and the control keeps `space-1` round its words (less a rule where it fills a head) so the ring stays a hairline clear of their letters (v9; checked on the ink of the words). `tools/audit.mjs` checks every ring as painted, in both themes and at both pointers, also with a mouse over the control: never cut by an ancestor, 3:1 on what is behind it.
- **A token is defined once, by its theme.** No component, page or script redefines one below it (a component that needs another value uses a variable of its own, as the page state's larger mark does with `--mark-size`): `check.mjs` fails such a declaration and `tools/audit.mjs` fails any element whose token differs from its theme's (v7 review, W23 and W24).
- **Charts** take colour from `series-1` to `series-8`. The order is fixed and the colour belongs to the series, never to its rank: a view hands out slots in palette order as series first appear in it (largest first); what a person sees wins: a series on screen never changes colour, and the largest series on screen is never grey while a slot is open (a series that a filter hides or that is not in the result is not on screen), whichever way the screen changed; a series that leaves and comes back takes its slot back unless a series on screen holds it, so a query edited to other series and back returns every colour; "Colour the eight largest" is offered only when pressing it would change a colour, that is, when one of the eight largest series on screen is not coloured (v9: every response meaningful); a shared link carries the map (Chart, "The algorithm"). Past eight, the rest are ONE "Other" entry in `series-other`: one band, one legend row, never a line or a row per folded series. Odd slots are a darker step and even slots a lighter one, so neighbours differ in lightness; slots 5 to 8 are dashed, so where hue and lightness repeat the dash tells them apart. Every slot reaches 3:1 on every surface a series or its swatch rests on (`ground`, `raised`, `sunken`, `hover`, `rule`) in both themes; on `pressed`, which lasts as long as a finger is down, the swatch's own `ground` ring carries it. Series colours never appear outside a chart and its legend, and action and status colours never appear as series (each slot is measurably apart from every one of them). Chart text is `ink-secondary` or `ink-muted`, never the series colour. The full rules, with the algorithm, are in Chart.
- **Traces and logs are neutral.** A trace's spans (Waterfall) are bars in `ink-muted`, and in `ink` with a strong name where a span's own time is a tenth of the trace or more: lightness and weight say where the time went, because a span is not a series and its length is not a state. Log lines (Log) carry their level as a word, with the status mark for `error` and `warn` only. A failed span or an error line has its status mark; a matched search term is `vz-match`, weight on `rule`, like an insertion in a diff. Neither ever takes a series, action or status colour as a fill.

## Type

- Set interface and reading text in the `sans` family (Schibsted Grotesk), and every number a person compares or identifier they copy in `mono` (JetBrains Mono). Both are served from this system's own files, never from a third party. Preload the sans file in the page head (`<link rel="preload" as="font" type="font/woff2" crossorigin>`); it has a metric-matched fallback so text does not move when it arrives. The files cover Latin and extended Latin; the mono also covers Greek and Cyrillic. Other scripts fall back to the system font.
- Any number that is compared in a column or updates in place is set in `mono`, which is fixed-width, so it does not shift as it changes. The sans is not set to tabular figures: this face widens full stops, commas and colons to digit width when asked, which breaks prose.
- A number with its unit inside a sentence is one `vz-qty`: mono scaled to the sentence (`qty-scale` of its size, never below `data` size) on the sentence's own line, unbreakable, with a thin space before the unit. It works in `ui`, `body`, a heading and the page's state line, so one event's "13:07" is set the same way everywhere. Never `vz-num` inside prose: its full-width space and taller line open gaps in the sentence (Number).
- Component code uses the type styles as `var(--text-<name>)` and never writes a size. `micro` (mono, 11px) is the smallest text, for keyboard hints and chart axes.
- Use `ui` for interface text and for the labels of untoned buttons; `ui-strong` for toned button labels, selected items and panel titles. Use `body` for prose, at a measure of 60 to 72 characters (`measure`). Components take weights from the type tokens (`--text-ui-strong-weight`), never as numbers.
- Use `display` at most once per page, for the name of the thing being looked at. Use `title` for page and dialog titles, `heading` for sections.
- Column heads and field labels use `label`: sentence case, weight 500, `ink-secondary`. Do not set text in capitals anywhere, and do not letter-space anything; the negative tracking in `display`, `title` and `heading` is part of those styles.
- Numbers in tables use `mono` and align right (checked as rendered for every column of bare numbers on every page). Put the unit in the column head, once, and leave the cells bare. The one exception is a column whose cells have different units ("912 ms", "4 min 10 s", "1.3%"): it is left-aligned, each cell with its own unit. A single large figure (`vz-stat`) is the one exception: it uses the sans at `display` size, and its container reserves the width of its longest expected value so a changing figure does not move what is beside it.
- Weights are 400, 500 and 600 for the sans (500 only for `label`), 400 and 500 for the mono. No italics for emphasis.

## Space and shape

- Spacing comes from the scale: `space-half`, `space-1`, `space-2`, `space-3`, `space-4`, `space-6`, `space-8`, `space-12`. Relatedness is distance: `space-1` inside a control, `space-2` between related controls, `space-3` between a section's heading and its content, `space-6` between panels, `space-8` between sections. A section is `vz-section`; a column of sections is `vz-sections` (a `vz-split` column already is one), so a heading always sits closer to its own content than to what is above it.
- Prose inside a page is `vz-text` (or `vz-secondary` in `ink-secondary`, for the sentence beside an action or under a title): margin 0, `measure` wide. No preview or screen writes its own margins.
- Rows of controls that can wrap are `vz-controls` and stacks of form controls are `vz-stack`, never hand-laid flex rows: wrapped rows are at least `space-3` apart (more with a coarse pointer), and two toned buttons in one row are `space-6` apart, so a slip never reaches a destructive or cautionary action.
- Controls are `control-md` tall (`control-sm` in toolbars and rows). Table rows and menu items are `row` tall. Icons are `icon`.
- Radii by role: `radius-0` for anything that tiles (tables, panels), `radius-1` for marks inside controls, `radius-2` for controls, `radius-3` for overlays. Nothing is fully rounded.
- A panel is a region with a 1px `ink` rule above its title. It has no box, fill or shadow. Do not put a panel inside a panel.
- `shadow-overlay` is the only shadow, and it means "this floats".

## States

Every interactive element defines: rest, hover, focus-visible, pressed, disabled, and busy if it starts work. That includes the small ones: legend rows, sortable heads, menu rows, quiet buttons, a link. A press is `pressed` (or the tone's `-pressed`), painted in the next frame, never eased, and it outranks hover, **for every pointer**: a page loads `viz-press.js`, which marks the pressed control `data-pressed` from `pointerdown`, because browsers apply `:active` to a finger only at the release (v5 review, M3); every `:active` rule has its `[data-pressed]` twin. A scroll that starts on a control shows its press until the browser takes the gesture as a scroll (12 to 84 ms in the v6 review), as native controls do; holding the mark back until the finger is still would put every press a frame late, which the first budget row forbids (v6 review, m2: accepted, and said here). Busy (`aria-busy`) holds the pressed fill, never eases, and ignores a second press. A choice that holds (a checked menu row, a chosen segment, a chosen legend row, the table row whose detail is shown) is marked by weight and a tick, an underline or an edge on `rule`, never blue.

**After an action, with undo.** An action that changes something someone else will see (acknowledge, silence, confirm a claim, apply a change) replaces its button, in place and at the same height, with `vz-done`: what is now true, as a status with its mark ("Acknowledged by you at 15:16", "Silenced until 16:16"), and a small "Undo" (or the action's opposite, "End silence"). Focus moves to that button. Nothing else on the page announces it; the change is its own confirmation. The thing's own state line keeps its words and takes the new state's mark ("Firing since 13:07" with the acknowledged mark); who did what, and when, is said once, in `vz-done` (v5 review, m4). A history list may record it as an event. If the server refuses, the button comes back with a failure notice under it (Notice).

Every data view defines: loading (keep the previous data visible), empty (say what was asked and that nothing matched), error (the message from the system, then what to change), partial (say what is missing). A page that has never had data is a first run, not an empty state (FirstRun). A background action that failed after the person looked away is a failure notice at the control that started it (Notice).

Disabled controls use `ink-disabled` on `sunken`. Invalid fields take a `status-critical` border and a help line that starts with the critical mark and says, in `ink`, how to fix the value.

**Chrome that describes data belongs to the data on screen.** A panel's title, unit, range, step, legend, accessible name and text form come from the result that is drawn. While a different query waits, or after it was cancelled or failed, the head says "Showing the previous query" and everything else stays the previous query's. An age is the age of what is shown.

## Responsiveness and feedback

**Budgets.** These are requirements. Each is measured on the reference setup with `tools/speed.mjs`: a mid-range phone's CPU and network (4x CPU slowdown, Fast 4G) at two layouts, a desktop window (1440 x 900, fine pointer: `fixtures/speed.json`) and a phone (400 x 800, coarse pointer, touch: `fixtures/speed-phone.json`), the fixture dashboard (`fixtures/`), the 75th percentile of 20 runs, with the median and the worst run beside it. The fixture includes a 36-series and a 200-series chart; a figure measured only on a few series is not a pass. A change that touches interaction reports them before and after, and says whether each number was measured on the system's fixture page (a floor) or on the application.

**Load.** Every sample records the machine's 1-minute load average when it was taken; every result records the core count and a calibration task timed before the runs. A timing row is judged only when most of its samples were taken at a load at or below the core count; above it the row is printed with its load and marked "not judged", neither passed nor failed, and it is measured again on a quieter machine. The calibration ratio is context only: it never makes a loaded run judged. Layout shift is judged at any load. Before and after are measured in the same session, alternating run by run (`speed.mjs --compare`), so they share the load.

| What the person does | The interface must | Limit |
|---|---|---|
| Presses, types, focuses, drags | Paint the pressed state, the character, the ring or the crosshair in the first frame after the input event, with a finger as with a mouse. Typing is measured in the real editor, key by key; a press is measured by the fill actually painted | input delay plus processing at most 50 ms |
| Changes something local: chart / table / text, opens a menu, changes theme, switches to a tab whose data is already loaded | Finish. No waiting state is allowed | 100 ms |
| Moves to a view, or a tab, whose data is not loaded | Show the shell and anything cached, and the region's waiting state | 100 ms |
| Runs a query | Send the request and show the region's waiting state | 100 ms |
| Receives a result | Paint it; coarse data first, refined in place | 100 ms after it arrives |
| Interacts at all | Interaction to Next Paint | 200 ms |

The shell loads in at most 200 KB of compressed script. Layout shift stays under 0.05 at both layouts, including a page that loads already scrolled to a chart (as a reload does): every region reserves its final size before its data arrives, in its markup, from the same custom properties its parts are drawn with, so the coarse-pointer sizes reserve themselves and a chart skipped off screen is the height it draws (Chart, "Reserved height"). `tools/audit.mjs` reloads every page that has a chart while scrolled to each chart, and jumps to each after load, at both layouts, and fails a shift of 0.05 or a chart that does not land where it was (v9; the v8 review's B1). In that pass the 400 px layout's pointer is made coarse in the browser itself, by a command-line switch (`--blink-settings`, with `isMobile` for the phone's viewport), and not by DevTools touch emulation (Playwright's `hasTouch`), which every other pass uses. Touch emulation does not survive a navigation: the document a reload is replacing loses it before it is hidden, its pointer turns fine, its `@media (pointer: coarse)` rules stop applying, and the browser records and restores the scroll position of that shorter page. A reload measured under touch emulation therefore lands elsewhere at random on any page that sizes things by pointer type, which is the tool and not the page (v9, second review, B1 waived: `reviews/system-v9/second-review.md`). A phone's pointer is a fact about the device that no navigation changes; the switch stands in for that and is not a phone. It is a Chromium internal, so the pass fails if `(pointer: coarse)` does not match. Any check that reads a position, a size or a pointer-dependent style across a navigation at the phone layout needs the same pointer. The pass counts every layout-shift entry, those the browser marks as following input included: it gives no input, and with `isMobile` the browser marks the shifts of about the first half second of a load that way. `tools/speed.mjs` counts a marked shift from before its first input for the same reason. Chart crosshairs and brushes follow the pointer without triggering layout. Fonts are self-hosted, so first paint never waits on another host.

**Feedback has to be meaningful, accurate and useful.**

- *Meaningful.* Give feedback only for a change the person caused or needs to know about. If the result is visible, the result is the feedback: no success toast, no checkmark animation. Nothing under 100 ms gets an indicator.
- *Accurate.* Never draw progress that is not measured. A bar needs a real numerator and denominator; without one, show the stage and elapsed time. Do not show skeleton shapes that differ from what will arrive. Do not present old data as current: say how old it is. An optimistic change is allowed only when it can be undone, and a failure is shown where the change was made, with the old value restored.
- *Useful.* Say what the system is doing in terms the person can act on ("Scanning 12 of 40 files"), and offer the next step (Cancel, Narrow the range, Retry). Keep the previous result visible and interactive while the next one loads. Keep focus and scroll position where they were.

**Waiting, by duration.**

| Wait | Show |
|---|---|
| under 100 ms | nothing but the result |
| 100 to 400 ms | nothing new in the region; the control that started it is `aria-busy`: it holds its pressed fill and ignores a second press |
| over 400 ms | `vz-progress` over the top strip of the region (below), kept at least 300 ms once shown; the panel head says "Showing the previous query" if the query changed |
| over 2 s | the same, plus Cancel |
| over 10 s | the same, plus the cheaper alternative (a shorter range, a rollup) |
| over 60 s | stop, keep what arrived, and say so: "Showing 31 of 40 files. 9 timed out." with Retry |

- **Where the waiting line goes.** Every view in a panel starts with a strip of words about the data, never the data: a chart's strip above the plot (unit and marker words), a table's caption (count and order). The strip is `space-6` tall, and `control-touch` with a coarse pointer, so Cancel's hit area lies wholly over it. The waiting line lies over that strip, right of a chart's value axis. Nothing is reserved for it alone, nothing moves when it comes or goes, and it never covers data, a unit, a tick or a column head.
- **Automatic refresh never shows progress.** It replaces the data and the age in the panel head. If it fails, the old data stays and the age keeps growing; after three failures the panel head says "Not updating" with the reason.
- **Offline or stalled.** Say so once, at the top of the page, in a banner; keep everything already loaded usable; retry by itself and remove the banner when the connection returns.
- **Live tail** shows the newest line's time and a count of lines not yet shown when the person has scrolled away; it never moves the view by itself.

**Every form factor.**

- Lay out by the space a region has, not by device: panels reflow with container queries. The two widths are tokens, `breakpoint-narrow` (640px) and `breakpoint-wide` (1200px): twelve columns from wide, six from narrow, one below. No other width appears in a condition (`check.mjs`).
- Nothing scrolls the page sideways, at any width from 320 px to 1500 px, at 200% zoom, with either pointer (`tools/audit.mjs` loads every preview, the reference, the fixture and the compositions in each, and fails on a page that scrolls sideways, a head or cell outside its table, something absolutely placed escaping a box that scrolls, or a word cut by an edge). A wide table scrolls inside its own container with its first column fixed; a strip that scrolls (a table, the navigation, tabs) shows a `rule-control` edge at its right while there is more to see.
- With a coarse pointer every control has a `control-touch` hit area, with no overlap. Drawn sizes do not change, with these exceptions, each because a hit area cannot reach past its own box there. Text inputs, selects, `data-mono` inputs and the query well become `control-touch` tall with `body`-size text, because smaller text makes mobile browsers zoom the page on focus. Tabs and navigation links gain `space-3` of vertical padding, because a scrolling strip clips any hit area larger than itself. A segmented control wider than its room wraps with `control-touch` less `control-md` between its rows, so its segments, drawn at their own height, keep their hit areas apart. The legend's action row keeps its small buttons' 44 px inside itself when they wrap, and a row of controls in a panel keeps a small button's hit area off the plot or table under it. Table rows that hold a link or a control, legend rows, menu rows and checkboxes become `control-touch` tall, so neighbouring targets cannot overlap; a row's key link fills its cell (in a folded row, the whole row, its name 22 px from the row's top); a table of figures with nothing to tap keeps its density. The strip above a chart or table becomes `control-touch` tall (Panel). A link that stands alone is a control and gets the touch height. **A link inside running text (a paragraph, a list item's sentence, a help line) is text and keeps its line: it is exempt from the touch height, and so it is never the main path.** A link that is a key-value list's value stands alone. In a list of links and a timeline line, the link that is the item's own child stands alone; a sentence with a link in it goes in a `p` there. The main path of a flow (read the report, open the alert, see the change) is always a standalone link or a button: in a timeline, a line's link stands under its sentence (Timeline); in a banner, after it.
- Wrapped rows of controls keep their hit areas apart (`vz-controls`, `vz-stack`). Small controls are not stacked in adjacent rows by hand.
- **Menus** open anchored under the control that opened them (`vz-menu-anchor`), left edges aligned, flipped above when there is no room below; with a coarse pointer below `breakpoint-narrow` a menu is a sheet across the bottom of the screen, its rows `control-touch` tall. A menu that confirms a cautionary choice holds a sentence (`vz-menu-note`) and its confirming button (Menu).
- Nothing depends on hover or on a modifier key a phone lacks. Anything revealed on hover is also reachable by focus and by tap; anything done with Shift or a drag has a button.
- Charts read by touch as well as by pointer: drag for the crosshair, "Zoom in" and "Zoom out" buttons, a tap on a legend row toggles that series. The readout is under the plot, never over it. Charts are drawn at the size of their region with fixed text sizes; they are never scaled like images.
- A table that a person reads row by row (monitors, dashboards, keys) folds below `breakpoint-narrow` of its width, or below `breakpoint-wide` when it has more columns than fit in 640px (`data-fold="wide"`): its key and its one or two priority columns stay as columns and the rest become a second line under the key (Table). A kept column is `keep` wide (a quarter of the row) and never narrower than its longest phrase, and its state wraps between words; the key keeps at least `key-min` (half the row), a long identifier in it cut in the middle and a long name wrapped, never drawn over its neighbours; below `breakpoint-narrow`, with two kept columns, the key has its line to itself and the kept columns open the next; the row's "Actions…" never shares the key's line: it ends the next line, at the row's right edge (v6 review, B1). `tools/audit.mjs` fails a word whose centre belongs to another element and a key narrower than `key-min`, at every width, zoom and pointer. **A folding table never scrolls sideways**: one whose columns do not fit 640 px folds below `breakpoint-wide` (`data-fold="wide"`). A table people compare across many numeric columns scrolls inside its region with the first column fixed, its long identifiers cut in the middle (`vz-cut`).
- The interface works at 200% zoom and with enlarged text.

## Motion

- A press and a hover change state in the next frame, with no transition. **No colour is ever eased** (v8; before, hover eased its fill over `duration-fast`): a change of theme moves every colour at once and must be drawn whole in one frame, and an eased colour would start a transition on every control and show the old theme after the change counts as done. `check.mjs` fails a transition that names a property carrying a colour, however it is written (a logical longhand such as `border-block-end-color`, a shorthand, `all`), a property list taken from a custom property (it cannot be read), and a duration with no property list in its rule (it eases the initial list, `all`); `tools/audit.mjs` reads what every element eases as computed, at rest and under a hovering mouse, and counts the colour transitions running in the frame a change of theme is drawn, on every page, at both pointers (v9: the v8 review's V2b and V3 passed the earlier check); `tools/speed.mjs` counts them on the fixture: none. `duration-fast` stays a token, for an opacity change that needs one; no component uses it. Things that enter or leave (menus, dialogs) take `duration-slow`. Two curves: `ease` (`cubic-bezier(0.2, 0, 0, 1)`) for everything that moves, and `ease-measured` (linear) for a progress bar moving between two measured values, because easing it would show an acceleration nobody measured. A strip's scroll edge follows the scroll position, not the clock.
- Animate opacity and position only. Nothing loops, bounces or draws attention to itself. Data never animates into place.
- Honour `prefers-reduced-motion` by removing transitions.

## Words

- Write from the reader's side: what happened, then what to do. "The query touched 2.1 million series and was stopped. Add a label matcher."
- Buttons are verbs that say what will happen: "Run query", "Delete dashboard". Not "OK", not "Submit".
- Sentence case everywhere. No exclamation marks, no emoji, no apologies.
- Numbers carry units. Ages are "just now" under 5 s, then seconds, minutes and hours ("12 s ago", "14 min ago", "3 h ago"), and the absolute time beyond a day ("17 Nov, 09:30"). Never "0 s ago". Minutes are "min", never "m". Durations have at most two parts, largest first: "2 h 9 min".
- One event has one time everywhere: the page head, the list, the chart marker and the timeline say the same "13:07", and figures shown together agree with each other.
- Parts of a line are separated by a full stop and a new sentence, or by space; a middle dot separates only the parts of a panel's meta and of a legend name. Never put a separator against a mark.
- State how complete a result is. If it was sampled, truncated or rolled up, say so next to it.
- **Anything an agent wrote says so where it is read**, not once per page: a claim carries "Agent's claim" and "Not verified" until a person confirms it, and links to the query behind it; a shorter sentence starts "Agent:". Agent text is marked by a `stroke` rule down its left edge in `ink-muted`, which nothing else uses (Claim). It never appears as a status word, a stat, a title or a measured figure without that marking.

## Iconography

Use icons only where they are recognised faster than the word they replace, and pair them with a text label. One set, drawn at `icon` with a 1.5px stroke in the text colour beside them. No filled icons, no coloured icons, no emoji. This system ships no icon files yet; until it does, use words: a row's menu is a quiet small button "Actions…", the ellipsis saying it opens a menu.

## Layout

- The `hidden` attribute hides any element inside `.vz`, whatever display its component gives it (v9: the fixture's hidden chart and hidden view were drawn, because `.vz-chart` and `.vz-page` set their own display).
- The page gutter is `space-6` on wide screens and `space-4` below 640px (`vz-page`, and the navigation's own gutter). Content is left-aligned. Nothing is centred except a dialog on its scrim. The navigation's right-hand group (tenant, settings) starts with `vz-nav-end`.
- A page starts with `vz-page-head`: the title, a state line for a thing that has a state, a sub-line that says how fresh the page is, and the actions, which drop below the title as one row rather than squeeze it (PageHeader).
- Dashboards are a 12-column grid (`vz-grid` in `vz-dashboard`) with `space-6` gaps, six columns below 1200px of dashboard width and one below 640px. Panels align to it; their titles share a baseline across a row.
- Density is a feature. Prefer showing more rows to adding space, as long as rows stay `row` tall and text stays at `ui` or `small`.
