# Spike S10: traces and logs on Cloudflare, both flags on

The experiment `deploy/README.md` names under "From stage 3 of traces and logs" ("A trial on
Cloudflare"), and that the adversarial review `design/reviews/signals-end-to-end.md`, D62 ("Would
change if") and D71 ("Would change if") ask for: a staged deployment with `INGEST_SIGNALS` and
`QUERY_SIGNALS` on, OTLP traces, OTLP logs and Loki push through the gateway at realistic batch
sizes, the flush, ledger, compaction and publication of span and log files against real R2, and
Tempo and Loki queries back, measured on Cloudflare.

## Plan, names and worst-case cost (written before anything was deployed)

**From where.** A detached worktree of branch `claude/cloudflare-observability-platform-ibaqya` at
**`9d41dcaa53515aaf59db803fd7e4b7e4002a7f9f`** (its HEAD at 13:30 UTC on 2026-11-19; the commit is a
"Work in progress" snapshot whose own changes are a deploy test and shard bench files, none of them
deployed) in the scratch area, `node_modules` linked from the shared tree where every
`package.json` and `package-lock.json` matched (all 20 did), both WASM engines built there with
`CARGO_BUILD_JOBS=2` (`viz_engine.wasm` sha256 `381aae34…`, `viz_query.wasm` `26290d8f…`). The
stage is deployed with `deploy/deploy.sh --stage s10` from that worktree (`VIZ_SKIP_NPM_CI=1`,
`VIZ_WASM_PREBUILT=1`), so the shared tree's `deploy/resources.json` is never written.

**Exact names.** Everything is created by `deploy.sh`/`resources.mjs` (the stage) or by
`driver.mjs load-up` (the load Worker), and nothing else is touched:

| Kind | Names |
|---|---|
| Workers (stage) | `viz-s10-publisher`, `viz-s10-ingest`, `viz-s10-control`, `viz-s10-query`, `viz-s10-ruler`, `viz-s10-mcp`, `viz-s10-gateway` (only the gateway on workers.dev; no custom domain, no route; `vis.bitcru.sh` untouched) |
| Durable Object namespaces | `Publisher`; `Shard`, `Ledger`; `Tenant`; `Leaf`; `Ruler`, `Notifier`, `RulerIndex` (of the Workers above); `Client` of the load Worker |
| R2 / KV / queues | `viz-s10-lake`; `viz-s10-config`; `viz-s10-flush`, `viz-s10-maint`, `viz-s10-flush-dlq`, `viz-s10-maint-dlq` |
| Load Worker | `viz-s10-load-client` (workers.dev; every route needs `x-key`, a secret generated here; a service binding `GATEWAY` → `viz-s10-gateway`; Durable Object class `Client`, one object per client) |
| Secrets | viz-s10-control `OAUTH_CLIENT_KEY` (generated by the deploy); viz-s10-gateway `VIZ_BOOTSTRAP` (for each tenant's bootstrap, deleted by `bootstrap.mjs`); viz-s10-load-client `LOAD_KEY` and `TENANT_KEYS`. All on wrangler's stdin, none printed, logged or written outside the scratch area |
| Tenants | `s10-load` (the realistic load), `s10-q` (the query workloads, markers, metrics), `s10-fat` (the review's fat spans and fat logs), `s10-fatattr` (spans with their own 60 KB attribute) |

**Stage vars** (`VIZ_STAGE_VARS`): viz-ingest `INGEST_SIGNALS=traces,logs`, viz-query
`QUERY_SIGNALS=traces,logs`; nothing else. `--expires` (`VIZ_STAGE_EXPIRES_AT`) at most 3 hours after
the deploy; the load Worker refuses every request after its own `DEADLINE`, the same time.

**Timers and their deadline.** The load Worker has no alarm and no cron: a client works only inside
a request the driver makes, and nothing after `DEADLINE`. In the stage: the ruler's alarms and cron
stop at `VIZ_STAGE_EXPIRES_AT`; viz-ingest's hourly cron reads KV only when nothing is due; shard,
ledger and publisher alarms stop when their work is done. The stage and the load Worker are deleted
at the end; if the session were lost before that, what keeps running costs nothing measurable (the
hourly KV list), and the ruler is stopped by the deadline.

**Load, kept small.** At most: 6 realistic variants × 4 clients × 12 requests of 8,200 items (OTLP
traces and logs as gzip protobuf and gzip JSON, Loki as snappy protobuf and gzip JSON; the bodies of
`edge/bench/bodies.mjs`, byte-identical, generated per request with new ids); about 130 requests of
the query and fat shapes; 120 markers (each polled until found, at most 30 s); about 60 queries
repeated 2 to 5 times; the D71 bodies once each (about 40); 3 Remote Writes. With retries, at most
about 2,000 ingest requests and 40,000 query requests in the worst case.

**Worst-case cost, modelled** (Workers Paid list prices read 2026-11-19 from
developers.cloudflare.com/workers/platform/pricing/, **ignoring the included allowances**):

| Item | Bound | US$ |
|---|---|---|
| Worker requests | 100,000 | 0.03 |
| Worker CPU | 5.5 M CPU-ms (2,000 ingest requests at 1 s, 40,000 queries at 50 ms, flush, compaction, publication) | 0.11 |
| Durable Object requests | 500,000 | 0.08 |
| Durable Object duration | 90,000 GB-s (70 objects active for 2.5 h at 128 MB: far above what they will be) | 1.13 |
| SQLite rows written / read | 500,000 / 50 M | 0.50 / 0.05 |
| R2 class A / class B | 50,000 / 200,000 | 0.23 / 0.07 |
| R2 storage | 2 GB for 3 h | < 0.01 |
| Queue operations | 60,000 | 0.02 |
| KV reads / writes | 200,000 / 20,000 | 0.10 / 0.10 |
| **Total** | | **under US$2.50 worst case**; modelled expectation about US$0.10 to 0.30, most of it inside the plan's allowances |

## Files

| File | What it is |
|---|---|
| `load/bodies.mjs` | Request bodies, generated inside the client objects: `edge/bench/bodies.mjs`'s realistic bodies (same LCG, same draw order: byte-identical with seed 7), query/README.md's "Memory" shapes (`mem-signals.mjs`), the review's fat spans and fat logs, markers, a Remote Write encoder |
| `load/worker.mjs` | The load Worker: `fetch` checks `x-key` and hands the operation to the `Client` object it names; a client runs `ingest`, `markers`, `query`, `raw` or `rw` through the `GATEWAY` service binding and reports status, time, the `X-Viz-*` cost headers |
| `driver.mjs` | Deploys and deletes the load Worker (secrets on stdin), records the stage's ids, runs each phase, writes results to the scratch state directory |
| `analytics.mjs` | Cloudflare's GraphQL analytics for a window: per-script requests, CPU and isolate and WASM memory per invocation (by event type); per Durable Object namespace CPU, GB-s, SQLite rows, memory; R2 operations and latency; queue operations and lag; KV operations; list-price cost |
| `inventory.mjs` | The account's Workers, buckets, KV namespaces, queues, Durable Object namespaces and custom domains by name, before and after, and the difference |
| `check-bodies.mjs` | Local, no network: the generated bodies against `edge/bench/bodies.mjs` and through edge's decoders |
